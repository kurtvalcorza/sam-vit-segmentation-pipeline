## Executive assessment

**Readiness: Needs revision.** The default path is well built. The snapshot and the ADE20K row groups are digest-pinned, the split is image-disjoint, two prompt-only baselines frame the result, the frozen model is scored on both prompts, the epoch is selected on a separate validation split, and the adapter reloads mask-for-mask. A Kaggle Tesla T4 record exists for this exact blob, and `tools/build_notebook.py --check` passes at this SHA. Five problems stop it from being ready:

1. **Run all needs a manual restart** after the in-kernel pip install. The exact-blob Kaggle record needed one: NumPy 2.0.2 was loaded and the pin installs 2.5.3 (SAM-M1).
2. **Reruns never reset to the pretrained decoder (SAM-M2).** `adapt` snapshots whatever weights the pipeline currently holds as its "frozen" state. Rerunning Section 6 then Section 7, as the optional experiments and the BYOD instructions invite, scores the adapted decoder as "frozen" and trains on top of it. In a CPU probe the rerun's epoch 0, labelled `frozen model`, scored 0.976 on validation against a true frozen 0.990.
3. **The BYOD minimum is wrong (SAM-M3).** The notebook says "at least eight images". The BYOD path validates every split against the 8-record minimum, so 49 images are rejected and 50 are the real minimum. An 8-image zip fails with `2 records; 8..5000 are required`, which does not name the split.
4. **Unconditional sample asserts stop BYOD (SAM-M4).** Cell 17 asserts that the frozen box prompt beats the centre-disk baseline. On round objects it does not: 0.9886 against 0.9964 in a CPU probe. A learner's BYOD run then stops with a bare `AssertionError` before training. Cell 21 also asserts a strict gain.
5. **The guided layer is missing (SAM-M5).** There is no how-to-use section, roadmap, glossary, prediction prompt, checkpoint, troubleshooting section, Infrastructure labelling or conclusion scaffold.

## 3. Findings

### Major

#### SAM-M1 — Run all needs a manual restart after the in-kernel pip install

- **Cell/section:** Section 1, cell 3. Generator: `tools/build_notebook.py:40–75` (install cell with `subprocess.run([... 'pip', 'install', '-q', *PINS])` at line 61).
- **Observed issue:** the cell pip-installs `torch==2.14.0`, `numpy==2.5.3` and the other pins into the running kernel, then raises `RuntimeError(... 'Restart the runtime, then rerun from the top.')` when a distribution that was already imported has changed version.
- **Consequence:** Run all stops at cell 3 on a fresh hosted runtime. The learner has to restart and run all again. This contradicts the opening ("Selecting **Run all** in a fresh supported runtime installs the pinned dependencies … no configuration edit").
- **Evidence (documented execution evidence):** exact-blob Kaggle T4 record (`run_summary.json`): pass 1 `RuntimeError: Core dependencies changed while older modules were loaded: cuda-bindings: loaded=12.9.4, installed=13.4.2; numpy: loaded=2.0.2, installed=2.5.3`, then `restarted_after_install_cell: true`. `docs/release-verification.md` records "11/11 ok (1 restart after install cell)". Colab preloads NumPy at a version other than the pin as well (inferred; not run here).
- **Recommended correction:** adopt the fleet's **uv isolated-environment pattern** rather than another install guard. A carrier cell bootstraps uv, creates a managed-Python venv (`uv venv --managed-python --python 3.12.12 <ROOT>/env`), installs a hash-locked `requirements.txt` with `uv pip install --require-hashes --only-binary :all:`, and runs the workload in that env, so the kernel's preloaded NumPy and torch are never replaced. Reference: `ast-audio-classification-pipeline/tutorials/DIMER_Sound_Event_Classification_Workshop.ipynb` on `origin/main` (also `bioclip2-biodiversity-pipeline/tutorials/DIMER_Philippine_Biodiversity_Field_Survey_Capstone.ipynb`). Change it in the generator and regenerate.
- **Acceptance check:** a fresh Colab runtime and a fresh Kaggle runtime each complete Run all of the regenerated blob in one pass with 0 restarts, recorded in `docs/release-verification.md` with the blob id.
- **Spec:** RUN1, RUN10, ENV6, REL11.

#### SAM-M2 — Reruns never reset to the pretrained decoder, so "frozen" numbers and the adapter record become wrong

- **Cell/section:** Sections 6–8 (cells 17, 19, 21); BYOD instruction in cell 0; optional experiments in cell 24. Code: `src/sam_vit_segmentation_pipeline/pipeline.py:581` (`frozen_state = {… model.state_dict() …}` taken from the *current* weights) and `pipeline.py:668–689` (`self.adapter` records only the latest call). Generator: `tools/notebook_template.py:73` (BYOD "re-run from that cell"), `:278` (frozen evaluation on `pipe`), `:475–476` (optional experiments).
- **Observed issue:** `pipe` is adapted in place. Rerunning Section 6 scores the adapted decoder under the `frozen_point` / `frozen_box` labels. Rerunning Section 7 starts training from the adapted weights, logs them as `epoch 0 … 'frozen model'`, can keep them as `best_epoch 0`, and `save_artifact` then exports them with a manifest recording the latest `prompts`/`lr`/`epochs` only. The BYOD instruction ("set `USE_BYOD = True` … and re-run from that cell") and every optional experiment in the Interpretation ("set `PROMPTS = 'point'` …; raise `EPOCHS` …; change `LEARNING_RATE` …") lead into this state.
- **Consequence:** a learner's comparison (frozen vs adapted, the baseline deltas, "did the click gain more?") compares the adapted model with itself or with a stack of runs. A BYOD run fine-tunes an ADE20K-adapted decoder while reporting the pretrained base. The exported adapter's provenance does not describe its weights.
- **Evidence (direct execution, CPU, torch 2.13, synthetic disc stand-ins 8/3/3, probe `P5_rerun_never_resets`):** true frozen test point IoU 0.98900; after one `adapt` (lr 1e-3, decoder drift 0.0079), a Section 6 rerun labelled "frozen" gives 0.95610. A second `adapt` (`prompts='point'`) logs epoch 0 `note: 'frozen model'` with val score 0.97601, equal to the post-adapt-1 score, not the pristine 0.99031. It keeps `best_epoch: 0`, so the record reads `{prompts: 'point', epochs: 1, best_epoch: 0}` while the weights are the mixed-prompt run's. (A first attempt with validation selection kept epoch 0 on these easy stand-ins and moved nothing; it is recorded in `results.json` as inconclusive.)
- **Recommended correction:** keep a pristine copy of the decoder tensors when the base pipeline is loaded (Section 3), and have Section 7 restore it before `adapt` (or build a fresh pipeline per experiment, as cell 23 already does for `frozen_base`). Score the Section 6 "frozen" numbers on a pipeline that is never adapted. Tell the learner exactly which cells to rerun for each optional experiment and for BYOD.
- **Acceptance check:** after a default Run all, setting `PROMPTS = 'point'` (or `USE_BYOD = True` with a valid dataset) and following the stated rerun instructions gives Section 6 frozen numbers equal to the first run's (same data), epoch 0 equal to the pristine validation score, and an adapter manifest whose config matches a single run from the base.
- **Spec:** UX7, GDL10, OUT8, ART8, DAT13.

#### SAM-M3 — The BYOD minimum is 50 images, not the stated 8, and the rejection does not name the split

- **Cell/section:** cell 0 (BYOD paragraph: "at least eight images"), cell 1 ("a dataset needs 8..5,000 records"), cell 13 (`dataset_manifests = {name: validate_dataset(part) …}`). Generator: `tools/notebook_template.py:75`, `:122`, `:173`; code `src/sam_vit_segmentation_pipeline/samples.py:434–454` (`split_dataset`, 20 % test, 15 % validation) and `:377–383` (`MIN_RECORDS = 8` per call).
- **Observed issue:** the BYOD branch splits the records and then validates **each split** against the 8-record minimum. Validation needs `round(0.15·n) ≥ 8` and test needs `round(0.2·n) ≥ 8`, so n ≥ 50.
- **Consequence:** a learner who follows the stated contract with 8–49 images gets a rejection after uploading. `2 records; 8..5000 are required` does not say which split failed or how many images are actually needed.
- **Evidence (direct execution, CPU, probes `P1_byod_minimum` and `P2_byod_zip8_through_cell13`):** for n = 8..60 synthetic records through the notebook's own `split_dataset` and per-split `validate_dataset`, the smallest passing n is **50** (n = 49 → `7 records; 8..5000 are required`; n = 50 → test 10 / validation 8 / train 32). An 8-image zip of image + `_mask.png` pairs loads 8 records, splits 5/1/2, and is rejected with `2 records; 8..5000 are required`.
- **Recommended correction:** either state the real minimum (50 distinct images under the default fractions) everywhere it is quoted, or validate the whole BYOD set against `MIN_RECORDS` and the splits against a per-split minimum with a message naming the split, its size and the total needed. Show the computed split sizes before the upload is used.
- **Acceptance check:** a BYOD zip at the stated minimum passes cell 13 and reaches the cell 23 export. A zip one image below it is rejected with a message naming the split, its size and the minimum total.
- **Spec:** DAT12, DAT14, DAT19, REL12.

#### SAM-M4 — Unconditional sample asserts stop a valid BYOD run before training

- **Cell/section:** cell 17 (`assert frozen_box['iou'] > baseline_disk['iou']`) and cell 21 (`assert adapted_point['iou'] > frozen_point['iou']`). Generator: `tools/notebook_template.py:284`, `:369`.
- **Observed issue:** both asserts encode expectations about the ADE20K sample and run on every data source. The centre-disk baseline is given the target's area, so on round targets it is close to perfect and can beat the frozen box prompt. - **Spec:** DAT13, RUN9, UX10.
